# Linguitect to TypeScript Adapter Specification

## 1. Adapter Metadata

```
@LANGUAGE_ADAPTER "Linguitect_to_TypeScript"
  @VERSION "1.0"
  @LANGUAGE_VERSION "TypeScript 5.x+"
  @TYPE "export"
  
  @METADATA
    @PARADIGMS ["object_oriented", "functional", "procedural"]
    @TYPING type="static" strength="strong"
    @MEMORY_MANAGEMENT type="gc"
    @EXECUTION_MODEL "transpiled"
    @TARGET_TYPESCRIPT_VERSION "5.x" # Default target version
  @END
```

## 6. Implementation Notes

### 6.1 TypeScript-Specific Features

TypeScript has several unique features that require special handling when translating from Linguitect:

1. **Type System**: TypeScript uses structural typing, which differs from the nominal typing used in many other languages. This means that type compatibility is determined by the structure of types rather than their names.

2. **Advanced Type Features**: TypeScript has a rich type system with features like union types, intersection types, conditional types, mapped types, and more. These need special handling when translating from Linguitect's type system.

3. **Type Inference**: TypeScript has a powerful type inference system. The adapter should leverage this when possible, but also provide explicit type annotations when necessary for clarity or correctness.

4. **Optional Chaining and Nullish Coalescing**: These modern JavaScript features should be used when appropriate for handling nullable or undefined values.

5. **Ambient Declarations**: TypeScript allows for declaration files (`.d.ts`) that provide type information for JavaScript code. The adapter should generate these when appropriate.

### 6.2 TypeScript-Specific Idioms

When translating to TypeScript, the following idiomatic patterns should be used:

1. **Interfaces over Type Aliases** for object types when possible
2. **Union Types** for values that can be one of several types
3. **Type Guards** for narrowing types in conditional blocks
4. **Optional Properties** using the `?` syntax rather than union with undefined
5. **Readonly Properties** for immutable data
6. **Discriminated Unions** for type-safe handling of variant types
7. **Async/Await** for asynchronous code instead of callback patterns

### 6.4 Environment Considerations

TypeScript code can target different JavaScript environments:

1. **Browser**: When targeting browsers, the adapter should consider browser APIs and compatibility.
2. **Node.js**: When targeting Node.js, the adapter should consider Node.js-specific APIs and module systems.
3. **Deno**: When targeting Deno, the adapter should consider Deno-specific APIs and import/export syntax.

The adapter should provide configuration options to specify the target environment.
